# MW4 DMZ Companion

An unofficial, fan-made companion web app for Call of Duty: Modern Warfare 4 DMZ.
It is built for a second screen: an interactive map, mission and loot tracking,
crafting and FOB requirements, progress tracking and guides.

> Not affiliated with Activision or Infinity Ward. All game data in the repo is
> currently **mock data**, clearly labelled in the UI, until verified sources are added.

## Stack

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript (strict) · Tailwind CSS 4 ·
shadcn/ui on Radix · Lucide icons · Leaflet with `CRS.Simple` · PWA (manifest + service worker) ·
Vitest.

## Getting started

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build
npm test           # unit tests
npm run lint
npm run typecheck
```

## Project structure

```
src/
  app/                 Routes only: thin pages, layout, loading/error/not-found, manifest
  components/
    ui/                shadcn/ui primitives (button, card, dialog, select, table, ...)
    layout/            App shell, sidebar and mobile navigation, service worker registration
    common/            Shared building blocks: page header, empty/error/loading states,
                       search, filters, stat cards, verification badge
  features/            One folder per feature: views plus their pure logic
    dashboard/  map/  missions/  items/  settings/
    progress/          Progress logic, stats, schema validation and the client store
  data/content/        Shared game data (versioned, each record with sources)
  services/
    game-data/         GameDataRepository interface + static implementation
    progress/          ProgressRepository interface + localStorage implementation
  providers/           React context for game data and progress
  hooks/               Reusable hooks
  lib/                 Utilities, game-data index (lookups and reverse relations)
  types/               TypeScript models: content meta, game entities, user progress
public/
  maps/                Map images (placeholder grid for now)
  icons/               PWA icons (generated by `npm run icons`)
  sw.js                Service worker
```

### Data architecture

- **Shared game data** (`src/data/content`) and **user progress** (`UserProgress`, in the
  browser) are separate. Progress is keyed by stable entity ids, so content updates never
  overwrite what a player has done.
- Every record carries `meta`: `verification` (`mock` / `unverified` / `verified`),
  `sources`, and the content version that last changed it. The bundle has its own
  `version` and `gameVersion`.
- Relationships are by id: missions → objectives → items/locations, items → locations,
  recipes → items, FOB upgrades → items. `buildGameIndex` derives reverse lookups
  ("which missions need this item?") and `findBrokenReferences` is enforced by tests.
- Both data sources sit behind repository interfaces (`GameDataRepository`,
  `ProgressRepository`), so Supabase can be added without touching the UI.

## Adding real data

Replace records in `src/data/content/*.ts`. Set `verification` to `unverified` or
`verified`, add at least one source, and bump `CONTENT_VERSION` in `meta.ts`.
Do not add missions, items or locations that are not sourced. Drop a sourced map image in
`public/maps/` and update `maps.ts` with its pixel size; location positions are image pixels
from the top-left corner.

See [docs/ROADMAP.md](docs/ROADMAP.md) for milestones.
